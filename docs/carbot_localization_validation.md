# 自动定位假收敛：验证版本与证据闭环

2026-09-30。本轮在 `codex/automatic-startup-localization` 完成隔离开发和实车验证。三个不同起点的自动定位、真实错误位姿拒绝、人工回退、近障退出以及无目标自动激活均已取得证据。默认模式仍只验证；显式 `--automatic-activate` 才会在质量门通过后激活 Nav2。

## 已实现的隔离与诊断

- 管理节点默认 `validation_only=true`；显式自动激活入口会覆盖为 false，并在通过全部质量门后调用导航 lifecycle。
- 默认质量检查通过进入 `CANDIDATE_READY` 并持续复核；显式激活模式通过后进入 `READY`。候选状态本身仍不能替代真实位置核对。
- 维护入口的 `--automatic` / `--validation-only` 均包含受控旋转，只产出候选；`--stationary-validation` 只激活定位、等待人工位姿，不触发全局撒粒子或旋转。
- 启动脚本检查目标管理节点的 `validation_only` 必须与请求模式一致；部署文件已备份、编译并完成开发机/Jetson 哈希核对。
- 扫描使用其 header 时间查询 TF；查不到时清除有效评分时间，不退回最新 TF。
- 扫描、里程计、AMCL 和粒子云拒绝重复、倒退、过期及明显未来的源时间。TF 只在源时间推进时累计窗口，中断后重建窗口。AMCL 的有意未来时间按当前 transform_tolerance=0.5 秒加余量，独立允许到 0.6 秒，仍需核对运行时 transform_tolerance。
- 人工回退清除旧位姿、粒子、评分与窗口，只接收回退发生后的源时间。尚需实车证明 AMCL 确实采用本次初始位姿，不能把消息到达顺序视作服务确认。
- 运动去抖期间不累计质量；停车需新鲜里程计。失败原因、候选位姿、扫描 TF 错误、源时间/接收时源年龄、评分耗时进入状态 JSON。
- 评分保持原门槛，增加所有采样束的已知/未知/地图外计数、端点命中数、穿墙比例和旧版分母评分。没有用新阈值替代实测。

## 数据采集与离线比较

所有命令是后续操作说明，本轮未执行实车命令。实测前先核对电池、停车、维护入口与现场操作者。

1. 在现场通过维护入口 `./start_real_nav.sh --stationary-validation` 启动定位与 RViz。Nav2 不激活。在真实位置、墙角距离和朝向确认后使用一次 `2D Pose Estimate`；记录参考误差和扫描整体对齐情况。
2. 必须等维护入口完成 `[5/8]` 零速链路检查、到达 `[7/8]` 静止验证后，才启动录包。录包器会增加 `/cmd_vel` 订阅者，提前录制会触发严格拓扑检查并停机；不得放宽该安全检查。在具有 Humble ROS 环境且能读取地图文件的目标容器运行：

   ```bash
   python3 scripts/localization_evidence.py record \
     --map /absolute/path/to/map.yaml \
     --output /absolute/path/to/new-session --seconds 90 \
     --artifact src/isaac_3d_lidar_bringup/isaac_3d_lidar_bringup/automatic_localization_manager.py \
     --artifact src/isaac_3d_lidar_bringup/isaac_3d_lidar_bringup/automatic_localization_quality.py
   ```

   录制地图、扫描、动静态 TF、两路里程计、AMCL、粒子、initialpose、状态与两级速度。保存地图文件校验值、Git 信息、显式 artifact 和运行参数。Git HEAD 不能代表未提交代码，因此部署源码必须作为 artifact 保存。工具不发送 ROS 消息或调用运动/激活服务。录制完成只表示 bag 元数据存在，**不表示主题完整或未丢帧**；先检查 rosbag info、源时间间隔和录制日志。上游点云采样、CPU 与回调排队剖析尚待补充。
3. 从录包开始的接收时间偏移选择人工校准完成后的静止片段：

   ```bash
   python3 scripts/localization_evidence.py export \
     --bag /absolute/path/to/new-session/bag --start 30 --end 40 \
     --output /absolute/path/to/stationary.json
   ```

   此初版只导出 `base_footprint` 扫描，不能用于旋转片段上的固定参考位姿。必须另从 `/odom` 与速度证据核对静止。完整 bag 保留 TF 和粒子用于根因分析，导出器不做自动真值推断。
4. 保存假设列表 JSON，每项为 `{"name":"reference","x":...,"y":...,"yaw":...}`，单位米/弧度、map 坐标、base_footprint 位姿。必须包含现场确认参考、历史错误候选（如已取得可靠数值）、相似区域以及附近位置/朝向扰动。没有历史数值时明确缺失，禁止从摘要编造。
5. 同一份扫描离线比较：

   ```bash
   python3 scripts/localization_compare.py stationary.json hypotheses.json \
     --output comparison.json
   ```

   报告逐帧输出旧/新评分、覆盖、穿墙、扫描门槛和通过比例，以及输入和配置 SHA-256。`navigation_accepted` 永远为 false。正样本通过、旧错误样本拒绝都需要真实记录支持；合成样例只能作为软件回归。

## 未完成且阻止恢复自动导航的项目

| 工作 | 必须取得的证据 |
|---|---|
| 实际位置参考 | 测量方法、位置/角度误差、操作者确认、RViz 对齐截图 |
| 历史假阳性复现 | 同一扫描在真实位置与错误候选下的逐帧指标；没有原 bag 则标注不可原样重放 |
| 时间与外参实测 | scan/TF 对应时间、运行外参、map→odom 唯一发布者、地图校验值 |
| 射线原点 | 当前扫描在 base_footprint 投影，非 MID-360 光学原点；比较虚拟原点与真实原点对穿墙判定的影响 |
| 选错根因 | 全局粒子随时间分布、不同区域竞争候选、错误收敛发生时间 |
| 性能 | 上游点云频率、扫描源与接收时间、评分/回调耗时、CPU、零速到实际停车时序 |
| 歧义拒绝 | 用真实正负数据验证候选比较的区分能力，再决定接入实时流程；尚未实现全图候选搜索 |
| 完整故障状态机 | 服务失败/部分激活撤销、TF authority 冲突、人工位姿采用确认、停止延迟的 ROS 集成测试 |
| 实车复测 | 3 个起点 × 2 个朝向 × 2 次，至少 12 次；错误候选拒绝与正确/错误人工回退各有记录 |
| 恢复自动激活 | 上述全部通过后单独解除软件锁；先无目标静止验证，再开机/服务延迟/重复启动验收 |

建议误差目标 0.20 m、5°，最终需结合参考测量不确定度确定。任何错误位置被接受即本轮失败。零误接受的有限样本不能证明所有场景可靠。导航行驶须另有明确目标。

## 本地验证边界

状态机测试执行生产方法，用确定性 ROS 边界替身；覆盖全质量通过不激活、直接进入启动状态仍被拦截、缓存 TF 不刷新窗口、重复/倒退/旧/未来消息拒绝、扫描时间 TF 查询失败、人工回退清证据、运动去抖不计质量。原有配置/安全测试继续保留。测试没有 ROS 网络和实车，也没有验证真实错误位置已被拒绝。

本轮本地结果：27 项测试通过，Bash/Python 语法检查通过。采集器 rosbag 录制/导出尚未在 Humble 实际环境执行；完整 ROS 集成、部署与实车验收均未完成。

## 2026-09-30 静止实车验证

本节取代上一段“工具尚未在 Humble 实际环境执行”的状态，但不解除自动导航锁定。

- 新版在 Jetson 的隔离 Humble 容器中通过测试并实际创建节点，确认 `validation_only=true`；部署前保存了旧源码备份，部署后源码与配置 SHA-256 和开发机一致。
- 第一份完整录包 `2026-09-30_localization_static_02` 持续 212.55 秒，包含地图、2105 帧扫描、2121 帧里程计、AMCL、粒子、TF、人工初始位姿、状态和两级速度。4191 个速度样本全部为零，Nav2 未激活。
- 操作者第一次人工标定后，AMCL 收敛到约 `(2.03, 3.34, -3.69°)`，扫描分数约 0.80、覆盖率约 0.99，但 14.93 秒验证未通过。录包证明该窗口 145 个里程计样本没有一个超过静止门槛；主要失败是 48 次 `SCAN_TF_UNAVAILABLE_OR_STALE_SCORE`，最长质量保持仅 1.545 秒。
- 根因是 `/scan` 与 `odom→base_footprint` 约同频，扫描回调经常比对应 TF 早一帧。旧实现按正确扫描时间查询一次 TF，但查询失败后永久丢弃该帧。现改为保留最多 3 帧扫描，只在对应时刻 TF 到达后重试；仍不允许使用最新 TF 代替。对应回归测试和既有测试共 28 项通过。
- 修复版第二次人工标定进入 `CANDIDATE_READY`。操作者确认实际位置及 RViz 对齐；候选为 `(2.0437 m, 3.3007 m, -0.05862 rad)`。实时指标为扫描分数约 `0.735`、覆盖率 `0.980`、TF 平移/偏航跨度 `0.012 m/0.001 rad`。`bt_navigator` 保持 unconfigured。
- 第二份正确位置录包 `2026-09-30_localization_static_03` 中，272 个状态样本全部为 `CANDIDATE_READY` 且无质量失败，556 个速度样本全部为零。导出的 20 秒静止片段包含 198 帧扫描。
- 同一扫描在正确候选上的逐帧通过率为 `1.0`，平均分 `0.752`、平均覆盖率 `0.989`。局部扰动显示评分在参考附近约 0.1–0.2 m 内存在平坦区；部分 ±0.20 m 和全部 ±10° 扰动被拒绝。这符合当前 0.20 m 初始误差目标，但参考测量的不确定度仍未量化。
- 对地图自由区以 0.4 m、30° 做粗搜，排除参考位置 0.5 m 半径后共评估 2676 个候选，再对前 40 个用 12 帧、120 束精评。最高空间分离候选距离参考 1.496 m，平均分仅 `0.406`，通过率 `0`；精评候选均未通过。
- 历史严重假阳性的精确 `(x,y,yaw)` 和原始 bag 未保留，因此本轮不能声称“原样重放了上轮错误位置”。全图粗搜证明当前真实扫描没有发现能通过的离散远处竞争候选，但不是连续空间完备证明。

证据文件位于 `calibration_data/2026-09-30_localization_static_03/`：`manifest.json`、`summary.json`、`stationary.json`、`hypotheses.json`、`comparison.json` 和 `candidate_search.json`。完整 rosbag 保存在 Jetson 同名目录。实车会话结束后已用维护程序关闭 Nav2/RViz、清除速度安全锁并恢复 web teleop 为未使能状态。

### 移车后的静止标定与持续角度偏差

- 移车后以 `--stationary-validation` 重新采集 `2026-09-30_localization_static_04`。三次人工 `2D Pose Estimate` 分别约为 `(3.662, 2.229, -92.03°)`、`(3.491, 1.979, -91.43°)` 和 `(3.463, 1.984, -99.94°)`；AMCL 均被扫描/地图似然拉回约 `-95.4°`。因此持续“歪”不能归因于操作者没有把箭头点准。
- 对同一静止扫描在候选周围 `0.50 m` 内以 `0.05 m/2°` 搜索，共评估 57,240 个刚体位姿。最优解约为 `(3.525, 2.125, -96.0°)`，与 AMCL 候选仅差 `0.089 m/0.63°`，说明 AMCL 已接近当前扫描相对于当前地图的局部最优解。
- 即使最优解的平均扫描分数也只有 `0.7953`，已知地图覆盖率 `0.9269`，射线穿墙比例仍为 `0.1465`。这表明一组刚体位姿无法让整幅扫描与地图充分重合；继续微调人工初始位姿或放宽质量门槛不会修复几何不一致。
- 运行时 `base_footprint -> livox_frame` 为平移 `[0.016, 0.000, 0.209] m`、RPY 约 `[-0.352°, -0.278°, +1.121°]`，其中雷达偏航与标定配置一致。当前证据排除了“部署漏掉已知雷达偏航”这一简单原因，但尚不能区分固定外参残差、3D 点云投影高度差异和累计地图局部畸变。
- 当前优先级改为跨多个静止位置测量墙线角度及横向残差：若各位置残差方向和幅度一致，校正固定外参或地图坐标变换；若残差随位置变化，修复或重建与当前扫描高度带一致的 nvblox 地图。完成前暂停受控旋转和自动定位验收，不把 `2D Pose Estimate` 的反复重试当作解决办法。
- 本次录包中 1142 个速度样本全部为零，Nav2 保持 unconfigured。会话结束后维护程序已关闭 Nav2/RViz、清除速度安全锁，并将 web teleop 恢复为未使能状态。

证据文件位于 `calibration_data/2026-09-30_localization_static_04/`；其中 `local_pose_search.json` 保存局部搜索结果，完整 rosbag 保存在 Jetson 同名目录。

### 多高度带静止诊断

- 在不发送初始位姿、不激活 Nav2、不发布运动命令的条件下，同时采集当前 `0.10–0.35 m` 扫描以及 `0.02–0.12 m`、`0.12–0.22 m`、`0.22–0.35 m` 三个诊断高度带。四组数据来自同一位置和同一 15 秒窗口。
- 使用相同地图、相同参考位姿及相同 `0.025 m/1°` 局部搜索，当前扫描最佳平均分为 `0.8001`、覆盖率 `0.9332`、穿墙比例 `0.1406`；高层扫描分别为 `0.8102`、`0.9448`、`0.1237`。中层扫描穿墙比例升至 `0.2000`，证明低/中高度回波是当前几何不一致的重要来源。
- nvblox 保存地图的 ESDF 切片为离地 `0.09–0.35 m`，当前扫描为 `0.10–0.35 m`，两者上下限基本一致；因此问题不是一个明显写错的高度参数。更可能是低矮物体相对建图时已变化，或保存地图在该区域包含累计毛刺。高层结果仍有 `12.37%` 穿墙，不能把高度带优化解释为根因已经完全解决。
- 待验证实现新增 `/scan_localization`：AMCL 与定位质量评分使用 `0.22–0.35 m`，原 `/scan` 继续供 Nav2 障碍层、近障停车和旋转安全联锁使用。安全扫描和定位扫描分别检查新鲜度，定位扫描不能削弱完整高度带的停车条件。29 项静态、安全和状态机测试通过。
- 证据位于 `calibration_data/2026-09-30_scan_height_bands_01/`。该实现尚未部署或用于实车定位，不构成恢复旋转或导航的许可；下一步是在静止模式中只做一次初始位姿，比较新旧扫描的 AMCL 收敛和 RViz 对齐，再决定是否保留该高度带。

### 高层扫描、错位拒绝与确定性全图搜索

- `/scan_localization` 已部署并完成静止实车复测。数据集 `2026-09-30_localization_static_05` 的 187/187 帧高层扫描通过，平均分 `0.894`、平均穿墙比 `0.0665`；同时采集的完整高度扫描平均分 `0.845`、穿墙比 `0.1098`。操作者确认蓝色车位置与车头方向正确；234 个状态样本均为 `CANDIDATE_READY`，463 个速度样本均为零。
- 将旧错误位姿约 `(2.044, 3.301, -3.36°)` 注入同一现场后，实时分数仅 `0.108..0.143`、穿墙比 `44.6%..47.1%`，系统进入 `WAIT_MANUAL_POSE`。随后正确的人工回退位姿恢复 `CANDIDATE_READY`，错误位姿拒绝和人工回退链路已有真实数据；两轮导航均未激活且速度全为零。
- 首次完整自动旋转达到 `6.312 rad`，AMCL 却收敛到错误房间，其可解释质量分仅 `0.015..0.028`、穿墙比 `97%..98.5%`，被安全拒绝。同一停车扫描的离线全图搜索在真实区域找到约 `(3.625, 2.025, -90°)`，分数 `0.878`、穿墙比 `0.0766`。这说明扫描/地图证据能区分区域，AMCL `likelihood_field_prob` 端点似然会在相似结构中产生错误粒子峰。
- 管理节点因此新增 `SEARCH_GLOBAL_POSE`：转圈停车后，以端点命中、地图覆盖和射线穿墙联合指标做粗到细全图搜索，识别远处竞争候选，通过后才给 AMCL 紧协方差种子。本地 29 项数学、状态机和安全回归测试通过。

### 第二次自动旋转的收尾结论
