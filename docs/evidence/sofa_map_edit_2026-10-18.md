# 实车地图：沙发挪动后修正 2D 导航地图（2026-10-18）

## 1. 起因

用近场通道做实车绕障测试时，车停在 (3.00, 3.665)，朝向 -96.7°，左侧离沙发只有 7–8 cm，原地卡住（RPP 不肯转向，也没有后退行为）。原因是沙发之前被往里挪过，`carbot_map_20260928_215841` 没有更新：地图上沙发边离车比实际远，全局规划把路线贴着真实的沙发走。

沙发保留在新位置，只修正 2D 导航地图（`.pgm`）上的沙发边。

## 2. 实测沙发面

数据：bag `output/issue1_robot/bags/near_detour_01`（未提交）的最后 20 s，车静止。取原始 `/livox/lidar` 离地 0.10–0.35 m 的点，用雷达安装外参和车的静止位姿转到地图坐标。每 5 cm 一行，取 3.05 < x < 3.45 范围内点的 x 的 10% 分位数作为沙发面：

| 行中心 y | 实测面 x | 地图上沙发边 x |
|---|---|---|
| 3.375 | 3.183 | 3.25 |
| 3.625 | 3.201 | 3.25 |
| 3.775 | 3.204 | 3.30 |
| 4.075 | 3.229 | 3.30 |
| 4.475 | 3.255 | 3.30 |
| 4.725 | 3.277 | 3.30 |

- 每行内 5%–50% 分位数相差约 1 cm，是一个平整的面。
- 对照：西墙实测 x = 2.077，地图约 2.10，定位偏差约 2 cm。没有扣除这 2 cm，让地图和车实际看到的一致。

## 3. 改动

- y 3.30–4.75 的每一行：从实测面所在的格子到地图上原有的沙发格子之间，全部设为占用。
- 只增加占用，不删除任何格子。共改了 46 格，改之前全部是空闲（254）。
- 文件名不变，直接替换 Jetson 上的 `maps/real/carbot_map_20260928_215841.pgm`：
  - 原图备份为同目录下的 `.pgm.bak-20261018`（sha256 `47cdaf3f…`）；
  - 新图 sha256 `96ea6a70…`。
- yaml、`.nvblx`、`.ply`、surface npz 都没改。3D 网格里的沙发仍是旧位置，相差几厘米。
- 地图哈希变了，旧的保存位姿第一次启动时作废，车自动搜索定位（实测 SEARCH_MULTI_VIEW 后 READY）。

## 4. 实车验证

重启导航（近场通道开），目标 (2.68, 5.85) 经过沙发这一段，车正常通过，没有再贴着沙发卡住。

第一次重启时，操作员在启动脚本最后 3 s 的 `/cmd_vel` 安全检查期间就在 RViz 里发了目标，脚本按设计判失败（`/cmd_vel produced a nonzero message during the safety check`）。等打印 `SAFE /cmd_vel=...` 之后再发目标就正常。
