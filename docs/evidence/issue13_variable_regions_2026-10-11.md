# Issue #13：易变区域（窗帘）（离线，2026-10-11）

本文是离线证据，**没有在实车上运行**。分支 `feature/issue13-variable-regions`，基于 PR #50。

## 问题

左下底墙的窗帘，建图时是拉开的，使用时是拉上的。窗帘区域的两次实车样本（sample_11/13）中，三维第一名都是真值（操作员确认），但分差只有 0.095 / 0.122，低于 0.15 的门槛，所以被拒绝。

## 做法

- **区域文件**：`config/localization/<地图名>_variable_regions.yaml`，内容是地图坐标系下的若干盒子，并绑定网格的 SHA-256，换图或重建后不会误用。launch 默认按地图名查找这个文件，找不到就表示这张图没有易变区域；也可以用 `surface_variable_regions:=...` 指定。
- **评分规则**：盒子内的地图表面被去掉（所以穿透检查也不再计入）；在某个候选位姿下落进盒子的观测点，不参与该候选的评分。适用于排名、拟合、支撑范围、粗搜索、局部起点和近邻检查，所有候选都用同一规则。
- **区域范围**：来自一致性检查工具在 sample_11/13 上的结果。窗帘面在 y ≈ −0.42 m（p5–p95 为 −0.47 ~ −0.32），x −1.15 ~ 1.2 m，高 0.36 ~ 1.8 m。盒子取 x −1.25 ~ 1.30、**y −0.55 ~ −0.30**、z 0.30 ~ 2.00。
- **加载失败的处理**：哈希不匹配时，decide 模式拒绝启动，record 模式告警并不使用区域。

## 区域必须小：第一版的教训

第一版把窗洞和窗外也包进了区域（y −1.10 ~ −0.30）。在 A_01（右上）去掉真值的反例中，42 对时间窗里有 **3 次接受了错误位姿**，接受的是左下的半圈双胞胎 (0.25, 0.035, −154°)。
- 它有 28% 的点落在区域内，被忽略了；
- 它穿过窗洞结构的射线，也不再算穿透。

不加区域时，它是被穿透检查排除的。用“被剔除比例上限”也挡不住：左下真值被剔除的比例是 17%~25%，和它的 28% 挨在一起。

改为只覆盖窗帘面后，窗洞和窗外的地图结构保留下来。窗帘拉上时，真值的射线停在窗帘上；窗帘拉开时，看到的正好就是地图里的样子；错误位姿则不能再借这片区域删掉证据。**区域只应覆盖真正会变的东西。**

## 结果（窄区域）

| 评估 | 不加区域 | 加窄区域 |
|---|---|---|
| 8 份实车样本 | 6 接受，sample_11/13 拒绝 | **8/8 接受**（sample_11 分差 0.169、拟合 0.744；sample_13 分差 0.227、拟合 0.796）；反例全部拒绝 |
| 多时间窗重复，6 个一致位置 | 351/351 | 351/351 |
| 多时间窗重复，窗帘位置 | 0/32 | **32/32**（最小分差 0.153） |
| 反例错误接受（383 次） | 0 | **0** |
| 合成：左下区域、窗帘拉上（348 视角） | 345 接受，0 错误 | 348 接受，0 错误 |
| 合成：全场地理想 / 退化（1098 视角） | 1098 / 961，0 错误 | 1098 / 960，**0 错误** |
| 完整决策链回放（6 份录包，区域已加载） | 6/6 READY | **6/6 READY** |

合成场景低估了窗帘的影响：合成扫描除窗帘外和地图完全一致，而实车现场还有天花板偏差、杂物等其他差异。所以实车录包上的结果（0/32 → 32/32）更有说服力。

## 风险

- 窗帘区域现在能过，但余量很薄：sample_11 的最小分差 0.153，门槛 0.15。实车上可能偶尔仍被拒绝。
- 只验证了两份窗帘拉上时的补录。窗帘拉开的补录（sample_14c）还在 Jetson 上，下次开机后补做。
- 区域依赖人工确认的场地知识，需要操作员在现场确认那一片确实是窗帘。
