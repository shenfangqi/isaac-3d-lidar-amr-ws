# 多候选共同安全探测：全自动定位后续开发计划

更新：2026-10-10。基线 `df4883d`。本轮用户要求实现主动平移消歧，并在额度低于 20% 时停止开发、留下计划；随后补充小车电量不足，需要关机，后续按离线条件处理。

## 最新目标与适用前提（覆盖旧方案）

目标是车在支持区域内随手放置后，自动完成定位并进入 READY，全流程不依赖人工给初始位姿。不是只移动一次再尝试定位，而是多步探测、持续更新候选、自动恢复的完整闭环。

用户已明确本阶段现场与静态地图一致、没有新增障碍；动态避障和现场新增障碍处理留到后续强化学习阶段。本版利用静态地图证明路径安全，不再把实时扫描近场未知本身作为禁止起步的条件。地图中的障碍、未知区域、地图外区域仍不能当作可通行空间；真实 footprint、定位不确定度及停车余量仍须纳入检查。

未定位不等于不能利用地图：在每一个合理位姿候选下检查同一个车体相对动作。两个候选朝向相反时，“车体前进半米”对应地图中不同方向；不要求到达同一个地图位置，只要求整条动作序列在所有候选下都安全。不能仅挑得分前两名忽略其他合理候选。

完全闭环的交付前提是支持区域可消歧且存在可执行路线。完全对称、没有共同安全动作等情况必须在场地可定位性分析中识别；必要时增加固定、雷达可辨认的非对称结构或绝对定位来源，再重新验证。软件不能凭相同观测保证唯一定位，也不能把拒绝或人工接管算作完成目标。此处只更新开发计划，不代表已经实现、部署或通过验收。

## 要实现的完整闭环

`静止全图搜索 → 保留全部合理候选 → 共同安全且可消歧的多步路线 → 执行短段 → 停稳采集 → 联合更新候选 → 重规划下一段 → 唯一可信 → STOP_AND_VERIFY → AMCL 接管 → READY`

候选与新观测冲突时自动停车、重新全图搜索，并在 odom 连续时用本轮运动与观测历史复核新候选。若发生搬动或 odom 重置，丢弃失效的运动链，自动开始新的静止定位会话；不能跨不连续 odom 拼接证据。硬件故障和预算耗尽仍安全停车，但这些是未完成定位，不能标记 READY。

执行中利用实际 odom 推进各候选，并重新检查剩余路径；定位采集在停稳后进行。选择动作的首要目标是获得候选间不同的预期观测，开阔度仅作次要指标。不凭单个候选位姿发送 Nav2 全局目标，不平均两个地图位姿。

## 阶段 1：场地可定位性分析与共同安全路线规划

先用现有静态地图、三维数据和已记录候选构建歧义清单。对每组候选搜索共同安全的多步路线，区分“找到路线”“有限搜索预算内未找到”与“已证明在限定模型下不可区分”，不能把搜索超时说成物理不可解。报告覆盖范围、地图版本、误差假设和未覆盖区域。

在已创建纯 Python 模块 `localization_translation_policy.py` 基础上新增地图策略，输入：

- 静态地图及版本、全部合理位姿候选及其不确定度、源时间下的 odom、真实多边形 footprint。
- 最大单段距离、剩余总路程/时间、平移停止距离与误差裕量。
- 地图已知自由/障碍/未知、候选集版本、odom 连续性及控制证据的新鲜度。

复用已有多边形几何，分别在每个候选下检查整段转动和平移扫掠，包含候选不确定度、运动误差及最坏停车延伸；不只检查目标点、车中心或候选中心位姿。任何合理候选存在碰撞可能即拒绝该动作。旋转与平移都使用相同明确的地图依据，旋转净空声明不能代替平移证据。

动作原语使用平台可执行的分段转向、前进、停车观测；“向右”须转化成转向加前进，不假定底盘可侧移。路线规划应支持多步前瞻，允许第一步没有立即信息增益、后续步骤才看到区分特征。依据实际雷达视场、距离、遮挡及可用三维高度预测各候选下的观测差异，优先提高最难区分候选对的可辨识度，再比较路程、时间和开阔度。预测信息增益只用于选动作，不能用于定位放行。

无可执行消歧路线的区域进入场地补强清单：明确需要在哪个可观测位置增加固定非对称特征，或采用哪种绝对定位来源。补强方案验证前，不承诺该区域全自动成功；对环境的实体修改另行安排。

阶段 1 测试：两个相反朝向候选的同一车体动作、某候选安全而另一个碰撞、候选不确定范围碰撞、地图未知/越界、路径中段和停车延伸碰撞、多步才能消歧、完全对称、无共同路径及搜索预算耗尽。用独立解析场景验证，不能为得到可行路径而删掉仍合理的候选。

## 阶段 2：实现独立的平移运动守卫

当前 `localization_contracts.py` 只定义 STOP/ROTATE/RELEASE；`localization_motion_guard.py` 和对应节点没有平移能力。不能把 linear.x 塞进 ROTATE 消息绕过协议。

新增版本化平移请求和状态字段，处理旧协议兼容，扩展 `ProbeLink` 和守卫节点。请求必须带会话、序号、租约、目标距离、速度上限和已验收的平移标定身份。

进度用源时间里程计计算：沿起始车体轴的投影决定是否到达；累计实际路程消耗总预算。横向偏移、偏航偏差、反向移动、odom 跳变、驱动状态异常立即停车。停车距离包括命令失效、守卫/补偿延迟、底盘 watchdog 与实测制动尾程。旋转 profile 不能充当平移 profile。

扩展现有纯状态机以接收地图共同安全扫掠证据，绑定地图、候选集、路线、当前 odom 和标定身份；不能把旧扫描预览简单改成 geometry_clear。每次控制 tick 检查里程计/控制状态新鲜度、路线执行偏差和证据版本；候选变化、地图变化或偏离已验证范围时停车重规划。近场扫描未知本身不否决已被所有候选下地图验证的路径；定位观测缺失仍不允许继续定位决策。到点提前停止并验证停稳，设置单段、总路程、总时长、次数和无进展预算。保留急停及单一速度发布权。

阶段 2 在机器人断电条件下用假时钟和消息桩验证：租约失效、旧消息重放、两控制源冲突、停止距离、传感器丢失、打滑/无进度、偏航漂移、预算耗尽、取消/急停、停车失败。物理标定未完成前保持默认禁用。

## 阶段 3：接入 manager 与联合定位

在 `automatic_localization_manager.py` 加入显式的平移策略与计划/执行/停稳状态。现有策略默认值保持不变。先只在完整搜索后的位置歧义触发；传感器、TF、搜索不完整或硬件故障不能伪装成可运动消歧。

保留移动前的全部合理候选及训练帧。新观测在同一个 odom 连续会话内变换：

`T_map_scan(t) = H_at_reference × inverse(T_odom_base(reference)) × T_odom_base(t) × T_base_scan(t)`

这个关系已由 `localization_hypotheses.py` 的 `scan_pose_in_map` 实现，支持平移；复用而非重复实现。用前后两个视角重新复核所有候选，不平均两次位姿。不凭一次局部 ICP 收敛就放行。

检查现有 `_start_next_view` 删除旧 HOLDOUT 的行为。联合决策应有移动前后都未参与搜索的验证证据，且不能用旧帧替代“当前传感器必须新鲜”的门槛。限定视角数和会话年龄，必要时更新 `collect_keyframes` 的视角选择，使平移差异不会被仅按 yaw 的筛选丢弃。

所有候选被新观测推翻时，停车完整重搜全图后才有资格接受；odom 连续时新候选必须回查移动前证据。新增候选后重新验证路径，不能沿用旧候选集的安全结论。将当前只处理一对视角的 `infer_after_translation` 扩展成有界多视角历史，保留关键区分观测和独立 HOLDOUT。三维复核用于实际可观测的高度特征，不通过降低放行门槛替代证据。最终仍需 STOP_AND_VERIFY、AMCL 接管和控制权释放。

阶段 3 测试：两个初始相似区域、移动后仅一个解释新观测；两次仍对称必须拒绝；正确候选初排第二但联合后第一；候选全部被推翻；会话被搬动/里程计重置；接受时输出的是当前时刻位姿而非起点位姿。

## 阶段 4：离线录包与仿真闭环

现有静止三维包和纯旋转包可用于局部可见性/盲区分析，不能证明平移能消歧或平移守卫已验收。先用解析场景或仿真生成带平移的新视角序列，记录候选变化、扫掠拒绝原因、停车/运动预算和全过程状态。

设置明确进展指标：候选数、最难区分候选对的分差、预测与实测观测差异；记录失败动作和访问历史，避免反复相同路线。验证多步规划、每段重规划、候选全部推翻后自动恢复、odom 重置后新会话以及最终 READY 接管的完整状态机。无进展或预算耗尽应给出可复现原因，不通过无限循环或自动转人工掩盖缺陷。

## 阶段 5：充电后实车验证与验收

需要机器人时提前通知用户，明确是静止检查、平移制动标定还是主动定位试验。电量不足期间不请求实车动作。

先在受控场地标定平移速度、停止尾程、侧滑与 watchdog，验收独立平移 profile。然后在两块对称区域分别验证一次短段移动闭环，检查新观察点是否实际打破歧义。无安全路径时保留拒绝原因，不请求人工给初始位姿来掩盖失败。

旧的“50 次、成功率 ≥95%”已废止，不作为任何阶段的验收标准。最终先列明支持区域和静态环境前提，完成歧义区域及消歧路线覆盖验证；再做至少 50 次分布覆盖、含对称区域/边缘/不同朝向的随机放车测试，要求全部无需人工位姿进入正确 READY，误定位为 0，每轮 ≤360 s。观测真值只用于验收核对，不输入定位算法。超时、无路径或安全拒绝均计为失败并解决后重验。有限次数通过不等于数学证明任意位置必成功；未覆盖区域仍须明确记录。修改规则或场地补强后重新累计正式验收。
