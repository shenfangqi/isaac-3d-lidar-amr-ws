## 反向第 3 次启动前通信门禁失败

- 第一次启动尝试在 SSH 建连前因 `ubuntu.local` mDNS 解析失败退出，没有发布
  任何速度命令；随后改用 Jetson 固定地址 `192.168.1.109`。
- 固定 IP 只读复核期间，约 18 秒内 `reconnect_count` 从 `24` 增至 `29`；
  `/wheel_ticks` 实测平均仅约 `15.5 Hz`，最大接收空窗约 `2.86 s`。
- Agent 日志显示 ESP32 客户端主动执行 `delete_client` 并销毁 session，约 1 秒后
  使用新的 client key 和 UDP 源端口重建；部分 session 仅维持约 1--3 秒。
- 固件 `main/ros_interface/ros_executor.c` 当前每 20 次 executor 循环执行一次
  `rmw_uros_ping_agent(100, 1)`；单次 100 ms ping 失败就退出执行循环、停止 ROS
  运动、销毁 ROS 实体并在 1 秒后重建。该健康检查判据过于敏感，且与 Agent
  观测到的反复主动销毁完全一致。
- ESP32 连续 30 次 ICMP ping 为 0% 丢包、平均约 `5.4 ms`；Jetson Agent 服务
  没有崩溃或自动重启，因此不支持“普通 Wi-Fi 已掉线”或“Agent 进程退出”的解释。
- Jetson `wlP1p1s0` Wi-Fi power save 为 `on`。尝试临时关闭需要 sudo 密码，命令
  未执行，系统设置没有改变。下一步应先关闭 power save 做静态 A/B 验证；若仍
  重连，则修改 ESP32 固件，避免以单次 100 ms runtime ping 直接销毁会话。
- 本门禁失败后未执行反向第 3 次运动。

## 关闭 Jetson Wi-Fi 省电的 A/B 结果

- 人工执行 `sudo iw dev wlP1p1s0 set power_save off`，确认运行期状态为
  `Power save: off`。该设置只保证当前运行期，Jetson 重启后的持久性尚未配置。
- 随后的 60 秒静态 bag：
  - `/wheel_ticks`：`49.98 Hz`，最大接收空窗约 `71.6 ms`；
  - `/imu/data_raw`：`49.98 Hz`，最大接收空窗约 `63.3 ms`；
  - 两者均无超过 `100 ms` 的空窗；
  - `reconnect_count` 在 60 秒内保持 `31`。
- 静态窗口结束后又发生一次会话销毁/重建，`reconnect_count` 增至 `32`。
  相比关闭前每 1--3 秒重建有明显改善，但问题没有消除。
- 原始数据：`static_transport_60s_ps_off_bag`。
