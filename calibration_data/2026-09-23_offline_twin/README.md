# Offline evidence-constrained twin validation

This directory records the 2026-09-23 validation performed while the physical
vehicle was powered off. No Jetson, MID-360 or ESP32 runtime was contacted.

## Evidence response regression

`evidence_response_regression.json` was generated by
`scripts/regress_evidence_response.py`. At the 20 ms control period it passed
the measured latency, directional response, compensation and stop-tail checks.

## Same-estimator-path validation

Isaac ran with:

```text
CARBOT_SIM_RESPONSE_MODE=evidence_degraded
CARBOT_SIM_ESTIMATOR_MODE=evidence_ekf
```

The isolated ROS domain ran `sim_evidence_state_estimation.launch.py`, which
uses the real `wheel_odometry_fused.yaml` and `mid360_wheel_ekf.yaml` files.
`scripts/validate_sim_evidence_ekf.py` commanded a bounded forward/turn sequence
and compared `/odom` against `/ground_truth/odom`:

- ground-truth samples: 500
- filtered samples: 404
- final position error: 3.96 mm
- final yaw error: 0.000771 rad (0.044 deg)

Encoder and IMU publication measured approximately 49.8 Hz and 199.4 Hz. The
degraded cloud was approximately 9.97 Hz. All DDS traffic used loopback-only
CycloneDDS on domain 47.

## Default navigation regression

The normal `ideal_navigation` stack passed every `start_nav_all.sh` health
check. A 0.4 m straight goal and a 0.4 m turning goal both returned `SUCCEEDED`
with zero recoveries and stopped at zero commanded velocity. Final goal errors
were 0.095 m / 0.00 deg and 0.095 m / 0.78 deg, respectively.

These results validate software contracts and deterministic evidence models;
they do not close the physical mass, COM, inertia, friction, multi-surface,
payload, motor-electrical, observation-jitter, or hardware e-stop blockers.
